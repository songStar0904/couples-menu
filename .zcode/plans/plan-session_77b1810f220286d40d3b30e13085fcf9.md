# 「情侣菜单」微信小程序 — 设计方案与实施计划

## 一、产品定位与核心玩法

**情侣专属点餐**：恋爱关系中的两人互为「主厨 🧑‍🍳」和「食客 🍽️」。主厨发布自己的专属菜单（真实拿手菜 + 心意服务，如"一个拥抱""陪你看一场电影"），食客用**心意值**下单点菜，主厨接单、完成履约，形成点餐→接单→完成→感谢的仪式感闭环。

- **角色可切换**：两人都能各自维护菜单、互点点单（A 点 B 的菜，B 也点 A 的菜），"菜单"页根据视角自动切换"浏览点餐 / 管理编辑"。
- **情侣绑定**：一方生成邀请口令（6位字符 + 二维码），另一方输入/扫码绑定；同一用户只能绑定一位伴侣；解绑需二次确认，解绑后数据保留但不可见。
- **心意值经济**：初始赠送 200 点；每日签到、完成点单、互动任务均可获得；点单按主厨定价消耗；完整账本可查。替代真实支付，无需商户资质。

## 二、五大模块功能设计

| 模块 | 核心功能 |
|---|---|
| **首页** | 情侣在一起天数卡片（可自定义纪念日）、对方动态（点了你/完成了你的单）、待处理事项提醒（待接单 N 个）、今日推荐菜品、签到入口、快捷导航 |
| **菜单** | 食客视角：按分类浏览伴侣菜单、菜品详情（图片/描述/定价/可约时段）、直接下单；主厨视角：菜品增删改查、上下架、"今日休息"开关、分类管理 |
| **发现** | 精选菜单模板库（"一人食补偿菜单""周末早餐计划"等主题模板）、心意服务创意灵感、情侣挑战清单；模板**一键导入**为自己的菜单；用户可投稿模板（先存草稿，审核后上架，无公开社区动态流） |
| **订单** | 双 Tab（我点的 / 点我的）、状态流转：待接单→已接单→已完成 / 已取消；取消规则（待接单可免费取消，接单后取消需对方同意，心意值退还）；完成后可发送"感谢 + 星级评价 + 想说的话" |
| **我的** | 头像昵称（微信头像昵称填写能力）、情侣关系卡（伴侣信息/在一起天数/解绑）、心意值余额与明细、签到日历、任务中心、设置（通知开关/主题色/隐私）、关于与反馈 |

## 三、技术方案

### 前端（原生小程序 + 自研组件，面向多端迁移设计）
- **框架**：微信原生小程序（WXML/WXSS/JS，无转译层）；语言 JavaScript。
- **可迁移性设计**（响应"日后迁移安卓/鸿蒙/iOS"的诉求）：
  1. `services/` 统一 API 层封装全部云调用，页面不直接碰 `wx.cloud`；
  2. `utils/` 纯函数工具 + 自研轻量 store（页面间状态共享）；
  3. 自研 UI 组件库对齐业界规范（类 TDesign 的 props/events 命名），样式全部走 CSS 变量主题化，未来可平移到 uni-app/Taro/ArkTS 重写。
- **自研 UI 组件库**（`components/ui/`，约 15 个）：navbar、button、cell、card、dialog、toast、popup、empty、skeleton、badge、tag、price、stepper、segmented、form-item 等。
- **业务组件**（`components/business/`）：菜品卡片、订单卡片、动态条目、心意值徽章、签到日历、模板卡片。
- **主题**：CSS 变量定义情侣双主题（暖粉/雾蓝，可自定义主色）；设计基调：圆润、柔和渐变、插画风空状态。

### 后端（腾讯云开发 CloudBase）
- **云函数**（Node.js 18，按领域拆分，7 个）：
  - `user`：登录（openid 建档）、资料更新、设置
  - `couple`：邀请码生成/绑定/解绑/关系查询
  - `menu`：菜单/分类/菜品 CRUD、上下架、休息开关
  - `order`：下单（**事务扣心意值**）、接单/完成/取消/评价、列表
  - `points`：签到、任务完成、账本查询（余额变动全部走云函数，前端只读）
  - `discover`：模板列表/详情/一键导入/投稿
  - `notify`：订阅消息推送（下单提醒主厨、接单/完成提醒食客，模板 ID 线上配置，代码预留）
- **云数据库集合**：`users`、`couples`、`menus`（菜品，含 type: dish/service、定价、状态）、`orders`（状态机、心意值流水引用）、`point_records`（账本）、`sign_records`（签到）、`templates` + `template_items`（模板）、`submissions`（投稿）、`dynamics`（动态流）
- **云存储**：头像、菜品图、模板封面（前端直传 + 临时链接）。
- **安全**：所有写操作走云函数，按 openid 鉴权 + 校验情侣关系归属；数据库不开前端直写；订阅消息用云调用 openapi 免鉴权。

### 关键状态机与规则
- 订单状态：`pending → accepted → completed`，分支 `cancelled`（待接单单方取消；已接单发起取消需对方确认）。
- 账务一致性：下单/取消/奖励的心意值变动在云函数内用 `db.transaction` 保证原子性，`point_records` 记录前后余额。

## 六、成本与上线策略（已确认零成本可行）

- **不需要正式发布**：2 人私有应用用「体验版」长期使用——注册小程序（个人主体免费）→ 开发者工具上传 → 设为体验版 → 把伴侣加为体验成员（个人主体上限 15 人）→ 扫码即用，无需提审。
- **云开发费用**：
  - 新用户开通时选择**免费环境**：每月 40,000 资源点，免费 6 个月；
  - 2 人用量估算约 300~500 资源点/月（≈0.3~0.5 元），连免费额度 2% 都用不到 → **前 6 个月 0 元**；
  - 到期后可选：基础套餐 19.9 元/月，或按量付费（1000 点 = 1 元，2 人用量月成本 < 1 元）；数据量小，随时可导出迁移重建新免费环境。
- **前置条件**：仅需注册个人主体小程序 AppID + 开通云开发免费环境，无需认证费（无支付）、无需商户号。
