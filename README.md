# 情侣菜单 💕

> 为两个人打造的专属点餐微信小程序——TA 是你的私厨，你是 TA 的常客。
>
> 原生小程序 + 腾讯云开发，零图片资产（emoji 设计体系），双主题，**个人开发者零成本跑通**（体验版 + 云开发免费环境）。

## 核心玩法

1. **绑定伴侣**：一方生成 6 位邀请口令，另一方输入绑定，双方各得 66 心意值；
2. **上架菜单**：主厨创建菜品（🍳 拿手菜）和心意服务（💝 一个拥抱、陪你看电影）；
3. **用心意值点单**：食客下单扣除心意值，主厨接单 → 完成，心意值转入主厨账上；
4. **签到补充心意值**：每日 +5，连续 7 天额外 +10；
5. **发现模板**：精选菜单模板一键导入（周末早餐计划、深夜食堂……），也可投稿自己的菜单。

## 功能模块

| 模块 | 内容 |

| 📖 菜单 | 双视角：「去点单」（左分类右菜品，点单直达）/「我的菜单」（CRUD、上下架、今日休息、分类管理） |

| 👤 我的 | 微信头像昵称填写、情侣关系卡、心意值（签到日历/任务/账本）、设置（双主题/通知/纪念日） |

## 快速开始

### 1. 准备
- 微信开发者工具（最新稳定版）
- 注册一个小程序（个人主体即可，免费）拿到 AppID

### 2. 配置工程
1. 用开发者工具「导入项目」打开本目录；
2. 把 `project.config.json` 的 `appid` 改成你的 AppID（`touristappid` 可先游客模式预览）；
3. 工具栏「云开发」→ 开通云开发，选择**免费环境**（新用户每月 40,000 资源点，免费 6 个月，两人用量不足 2%）；
4. 把环境 ID 填入 `miniprogram/config/env.js`（只有一个环境可留空）。

### 3. 部署云函数
在开发者工具资源管理器中，对 `cloudfunctions/` 下**每个**目录（共 8 个）右键 →「上传并部署：云端安装依赖」：

```
user / couple / menu / order / points / discover / notify / init
```

### 4. 初始化数据库
1. 对 `cloudfunctions/init` 右键 →「云端测试」，输入 `{}` 运行——自动创建 10 个集合并写入 6 套精选模板；
2. （建议）云开发控制台 → 数据库 → 各集合 → 权限设置改为「仅创建者可读写」（客户端不直连数据库，全部走云函数）。

### 5. 运行
编译运行即可。真机预览 / 长期使用：上传代码 → 设为**体验版** → mp 后台把伴侣加为「体验成员」→ 扫码即用，**无需提审发布**。

## 目录结构

```
├── docs/                     # 产品需求 / 技术方案与数据库设计 / UI 规范
├── miniprogram/
│   ├── app.*                 # 全局配置、主题变量（CSS 自定义属性双主题）
│   ├── config/               # 云环境 ID、订阅消息模板 ID（占位）
│   ├── custom-tab-bar/       # 自定义 tabBar（emoji 图标，主题联动）
│   ├── components/ui/        # 自研组件库 11 个（button/cell/card/dialog/…）
│   ├── components/business/  # 业务组件 6 个（dish-card/order-card/sign-calendar/…）
│   ├── pages/                # 15 个页面
│   ├── services/             # API 层：页面不直接碰 wx.cloud，便于迁移多端
│   └── utils/                # store / 主题 / 时间 / 常量（错误码与云端一致）
├── cloudfunctions/           # 8 个云函数（Node 18, wx-server-sdk）
│   ├── user  couple  menu  order  points  discover  notify
│   └── init                  # 建集合 + 种子模板（部署后手动执行一次）
└── scripts/check.js          # 工程一致性检查（node scripts/check.js）
```

## 心意值规则

| 途径 | 数值 |
|---|---|
| 注册 | +200 |
| 绑定伴侣 | 双方各 +66 |
| 每日签到 | +5（连续 7 天额外 +10） |
| 下单 | 扣菜品定价（0 = 免费心意） |
| 完成订单 | 主厨收到全部定价 |
| 取消订单 | 食客全额退款 |

所有余额变动在云函数内用**数据库事务**保证原子性，`point_records` 记录每笔流水与变动后余额。

## 订阅消息（可选）

下单/接单/完成/取消通知已预留完整代码：
1. mp 后台「订阅消息」申请 4 个一次性模板；
2. 模板 ID 同时填入 `miniprogram/config/notify.js` 和 `cloudfunctions/notify/index.js` 的 `TEMPLATES`（字段名以实际模板为准，参考 `buildData`）；
3. 体验版调试把 `cloudfunctions/notify/index.js` 的 `MINIPROGRAM_STATE` 保持 `'trial'`，正式发布改 `'formal'`。

未配置模板时一切功能照常（只跳过推送）。

## 常见问题

- **云函数报 "collection not exists"**：先运行 `init` 云函数建集合；
- **登录报错**：检查 `config/env.js` 环境 ID、云函数是否全部部署；
- **图片传不上去**：云开发控制台 → 存储 → 确认已开通；云存储权限默认即可（走临时链接）；
- **订阅消息收不到**：需先在真机上允许订阅弹窗，且模板 ID 已正确配置；
- **想重置数据**：控制台删除集合后重跑 `init`。
