# 「情侣菜单」技术方案与数据库设计

> 版本 v1.0 · 2026-10-29

## 1. 总体架构

```
┌─────────────────────────────────────────────┐
│  微信小程序（原生框架，JavaScript）              │
│  pages → services(API层) → utils(store/工具)  │
│  components/ui(自研组件库) + components/business │
└──────────────────┬──────────────────────────┘
                   │ wx.cloud.callFunction（统一封装，带错误码）
┌──────────────────▼──────────────────────────┐
│  腾讯云开发 CloudBase（免费环境）                │
│  云函数 ×8（Node.js 18, wx-server-sdk）        │
│  云数据库（10 集合，仅服务端读写）                │
│  云存储（头像/菜品图）                          │
│  订阅消息（云调用 openapi，预留）                │
└─────────────────────────────────────────────┘
```

## 2. 技术选型

| 项 | 选择 | 理由 |
|---|---|---|
| 前端框架 | 微信原生小程序 + JavaScript | 无转译损耗、与云开发同生态、调试直接 |
| UI | **自研组件库**（components/ui） | 对齐 TDesign 命名规范（props/events），样式走 CSS 变量，便于日后迁移 uni-app/Taro/鸿蒙 |
| 状态 | 自研轻量 store（utils/store.js） | 全局仅 user/partner/couple/theme 四类状态，无需引入 mobx |
| 后端 | 腾讯云开发（云函数 + 云数据库 + 云存储） | 免运维、免鉴权（openid 注入）、按量付费有免费额度 |
| 云函数 | Node.js 18 + wx-server-sdk | 官方 SDK，支持事务/云调用 |

**面向多端迁移的分层约束**：
1. 页面禁止直接调用 `wx.cloud.*`，一律通过 `services/`；
2. 业务组件 props/events 命名与业界一致（model:value、bind:change 等）；
3. 颜色/间距全部 CSS 变量（`--cm-*`），主题切换只改变量值；
4. 工具函数（时间/校验/常量）为纯函数，可原样复用。

## 4. 云函数与 Action 清单

所有云函数统一返回 `{ code, msg, data }`；`code=0` 成功。身份一律取 `cloud.getWXContext().OPENID`，不信任前端传参。

| 云函数 | action | 说明 |
|---|---|---|
| **user** | login | 静默登录：按 openid 建档（首建送 200 心意值），返回 user/couple/partner |
| | updateProfile | 更新昵称/头像/签名 |
| | updateSettings | 主题/通知开关 |
| **couple** | createInvite | 生成 6 位口令（10 分钟有效，重建覆盖旧的） |
| | bindByCode | 校验口令→建 couple→双方 +66→清口令 |
| | unbind | 解绑（双方 coupleId 清空，couple 标记 dissolved） |
| | info | 查询我的关系与伴侣资料 |
| **menu** | my | 我的菜品 + 分类 + 统计 + 休息开关 |
| | partner | 伴侣上架菜品（按分类分组） |
| | saveDish | 新建/编辑菜品（校验归属，自动登记新分类） |
| | toggleDish / deleteDish | 上下架 / 删除 |
| | setMenuClosed | 今日休息开关 |
| | renameCategory / deleteCategory | 分类改名（同步菜品）/删除（菜品挪至"其他"） |
| **order** | create | **事务**：校验菜品→扣心意值→建订单→记账；动态+通知 |
| | accept / complete | 主厨接单 / 完成（**事务**：完成时把心意值转给主厨） |
| | cancel | 食客取消：pending 直接取消退款；accepted 转为"申请取消" |
| | confirmCancel / declineCancel | 主厨同意取消（退款）/ 拒绝（恢复已接单） |
| | list | 双 Tab 分页（快照冗余昵称头像，免联表） |
| | detail | 订单详情（校验参与方） |
| | review | 食客评价（星级+留言，仅一次） |
| | summary | 首页角标：待接单数/进行中订单数 |
| **points** | overview | 余额/今日签到/连续天数/任务列表 |
| | sign | 签到（+5，每满 7 天连签 +10，事务记账） |
| | ledger | 账本分页 |
| **discover** | listTemplates / templateDetail | 模板库 / 详情 |
| | importTemplate | 一键导入（同名去重、分类自动创建） |
| | submitTemplate | 投稿（status=pending） |
| **notify** | send | 订阅消息推送（模板 ID 未配置时仅记录日志，不报错） |
| **init** | setup | 创建 10 个集合 + 写入 6 套种子模板（幂等，可重复执行） |

## 5. 云数据库设计（10 集合）

> 全部集合权限设为「仅创建者可读写」；客户端不直连数据库，读写都走云函数（服务端不受权限限制）。

### users（_id = openid）
| 字段 | 类型 | 说明 |
|---|---|---|
| nickname / avatar / motto | String | 资料 |
| coupleId | String | 关系文档 id，空=未绑定 |
| points | Number | 心意值余额 |
| categories | Array<{name,sort}> | 我的菜品分类（注册默认 4 个） |
| menuClosed | Boolean | 今日休息 |
| settings | {theme:'pink'/'blue', notifyOrder, notifyAccept} | 设置 |
| createdAt / lastLoginAt | Number | 时间戳(ms) |

### couples
| 字段 | 说明 |
|---|---|
| members | [openidA, openidB]（2 个） |
| togetherDate | 'YYYY-MM-DD' 纪念日 |
| status | 'active' / 'dissolved' |
| createdAt / dissolvedAt | 时间戳 |

### invites
| 字段 | 说明 |
|---|---|
| _id | 口令码（6 位安全字符集） |
| openid / nickname / avatar | 邀请人快照 |
| expireAt | 过期时间戳（10 分钟） |

### dishes
| 字段 | 说明 |
|---|---|
| ownerId / coupleId | 归属 |
| name / type / category | type: 'dish' 菜品 \| 'service' 心意服务 |
| price | Number 心意值（0-9999） |
| desc / image | 描述 / 云存储 fileID（可空，空则用 emoji） |
| status | 'on' 上架 / 'off' 下架 |
| soldCount | 被点次数（冗余统计） |
| createdAt / updatedAt | 时间戳 |

### orders
| 字段 | 说明 |
|---|---|
| buyerId / sellerId | 点单人 / 主厨 openid |
| buyerName/Avatar, sellerName/Avatar | 冗余快照（列表免联表） |
| dishId / dishName / dishImage / dishType | 菜品快照 |
| price | Number |
| note / wishDate | 留言 / 期望日期 'YYYY-MM-DD' |
| status | pending → accepted → completed；分支 cancelled / cancel_requested |
| cancelBy / review{rating,message,createdAt} | 取消发起方 / 评价 |
| createdAt / acceptedAt / completedAt | 时间戳 |

### point_records（账本）
`{openid, delta, balance(变动后余额), type: register/bind/sign/order_pay/order_earn/refund, title, refId, createdAt}`

### sign_records
`{_id: openid_YYYY-MM-DD, openid, date, streak, reward, createdAt}`

### templates（种子数据）
`{title, subtitle, emoji, colors:[from,to], tags[], items[{name,type,category,price,desc}], sort, status:'published', useCount}`

### submissions
`{openid, nickname, title, desc, items[], status:'pending', createdAt}`

### dynamics（首页动态流）
`{coupleId, actorId, type: bind/order_create/order_accept/order_complete/review, text, refId, createdAt}`

## 6. 关键机制

### 6.1 订单状态机
```
pending ──accept──▶ accepted ──complete──▶ completed
   │                   │  ▲                    │
   │ cancel(食客)       │  └─declineCancel     └─review(食客,一次)
   ▼                   ├─ cancel(主厨=拒绝) ──▶ cancelled(退款)
cancelled(即时退款)     └─ cancel(食客=申请) ──▶ cancel_requested
                                │ confirmCancel(主厨)
                                ▼
                           cancelled(退款)
```
退款 = 食客心意值原路返还并记账。所有余额变动用 `db.startTransaction()` 保证「扣款-建单」「转账-状态」原子性，`point_records.balance` 记录变动后余额便于对账。

### 6.2 心意值账务规则
余额只允许云函数内 `_.inc()` 原子变更；每笔变动同步写 `point_records`；注册/绑定/签到奖励与订单退款遵循同一入口 `changePoints(tx, openid, delta, type, title, refId)`（各函数内实现，保持同构）。

### 6.3 错误码约定（前后端一致，utils/constants.js）
| code | 含义 |
|---|---|
| 0 | 成功 |
| 1001 | 未绑定伴侣 |
| 1002 | 已绑定伴侣（重复绑定） |
| 1003 | 心意值不足 |
| 1004 | 邀请口令无效或过期 |
| 1005 | 状态冲突（订单状态流转非法） |
| 1006 | 无权限操作该资源 |
| 1007 | 参数不合法 |
| 1 | 通用错误（msg 透出） |

### 6.4 订阅消息（预留）
- 前端在下单/接单前调用 `wx.requestSubscribeMessage`（try/catch 静默失败）；
- 云函数 `notify.send` 按 `config/notify.js` 的模板 ID 推送；ID 为空时跳过并记日志；
- 正式使用需在 mp 后台申请 4 个一次性订阅模板（新订单/已接单/已完成/取消提醒），把 ID 填入前后端配置。

### 6.5 通知订阅模板字段建议
`thing1 订单菜名`、`thing2 留言`、`phrase1 状态`、`time3 时间`（以实际申请到的模板字段为准）。

## 7. 部署与联调步骤

1. `project.config.json` 填入自己的 AppID（占位 `touristappid` 可先体验）；
2. 开发者工具开通云开发，创建**免费环境**；把环境 ID 填入 `miniprogram/config/env.js`；
3. 右键 `cloudfunctions/` 下每个函数 → **上传并部署（云端安装依赖）**；
4. 右键 `init` 云函数 → 云端测试，运行 `{"action":"setup"}`（建集合 + 种子数据）；
5. 控制台将各集合权限设为「仅创建者可读写」；
6. 编译运行；真机预览/体验版按 PRD 第 8 节流程。

## 8. 安全要点

- 身份服务端注入：所有写操作校验 openid 归属（菜品只能改自己的、订单只能参与方操作、couple 成员校验）；
- 越权防护：order/menu/points 全部按 openid 过滤查询；
- 金额（心意值）永不出现在可信前端：下单以数据库中的菜品 price 为准，不采信前端价格；
- 图片上传限定目录 `dishes/` `avatars/`，扩展名白名单校验。
